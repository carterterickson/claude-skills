# Session Document Format (Word Output)

Goal: the finished .docx should feel like a professionally laid-out adventure module the DM can flip through mid-session, not a wall of undifferentiated text. Read `/mnt/skills/public/docx/SKILL.md` for the mechanics of building the Word file itself; this file covers the layout/structure specific to session docs.

## Document structure

1. **Title block** — Session title, session number, in-world date, one-line "last time on..." recap (pull from Campaign Bible).
2. **Session-at-a-glance** — a short table or bullet list: scene list with type (combat/social/chase/etc.) and estimated time, so the DM can see the whole session's shape in 10 seconds and pace against the clock.
3. **Scene-by-scene sections**, each a clear heading (e.g., "Scene 2: The Duskwood Ambush"), containing in order:
   - Boxed read-aloud text — visually distinct (e.g., italicized and/or in a bordered/shaded text box or blockquote style) so it's instantly recognizable as "read this verbatim" versus DM notes
   - DM running notes — bullets, not paragraphs
   - NPC notes (if any) — name in bold, then hook/want/sample dialogue
   - Monster stat blocks (if any) — see below
4. **Appendix: Full Stat Blocks** — even though stat blocks appear inline in the scene where first used, if a monster recurs later or the document is long, consider a consolidated appendix at the end for quick lookup, cross-referenced by scene.
5. **DM cheat sheet** (last page) — a condensed one-page summary: key DCs used this session, initiative order reminders for planned fights, and the intended landing beat/hook for the session's end, so the DM can glance at one page instead of flipping through the whole doc during a tense moment.

## Formatting conventions

- Use real Word heading styles (Heading 1 for session title, Heading 2 for each scene, Heading 3 for subsections like "Stat Block" or "NPC Notes") so the document has a navigable outline/table of contents.
- Make boxed read-aloud text visually distinct from running notes — italics plus a shaded/bordered paragraph style works well and is easy to produce via the docx skill.
- Stat blocks should look like stat blocks: bold creature name/type line, a clean list of AC/HP/Speed/ability scores (a small table works well), then traits/actions as labeled bold-lead-in paragraphs — mirror the general visual grammar of published D&D stat blocks so it's instantly scannable, without copying any official book's exact layout/graphics.
- Use consistent, minimal color/shading (if used at all) — this is a working document read at a table, possibly printed in black-and-white, so don't rely on color alone to convey meaning.
- Keep paragraphs short. DMs skim mid-session; dense paragraphs slow them down.

## Length guidance

A single 4-hour session document is typically 6-12 pages depending on how combat-heavy it is (stat blocks take space). If producing 2-3 sessions ahead per the DM's request, give the first (next) session full detail and treat sessions 2-3 as lighter outlines (scene list, key beats, one or two draft stat blocks for anticipated fights) rather than full read-aloud-text-and-all documents — they'll get fleshed out to full detail once they become "next session." Say this explicitly in the document so the DM knows which sessions are print-ready versus still a working outline.
